Trimiterea datelor către server
folosind Fetch API
Descarcă lecția
În lecția anterioară ați învățat cum să utilizați Fetch API pentru a trimite cereri către server pentru a obține
date. Această lecție vă învață cum să folosiți Fetch API pentru a trimite date către server.
Trimiterea datelor către server se realizează prin formarea unei cereri HTTP POST. Pentru a crea o astfel de
cerere folosind metoda , este necesar, pe lângă calea definită prin primul parametru, să definiți și
fetch()
valoarea celui de-al doilea parametru – .
options
Configurarea metodei
fetch()
Metoda poate primi ca al doilea parametru un obiect prin care se configurează cererea care
fetch()
va fi trimisă către server. Cele mai importante proprietăți ale acestui obiect sunt:
– definește metoda HTTP a cererii; valorile acestei proprietăți pot fi " ", " ",
method GET POST
" " etc.;
DELETE
– definește antetele cererii HTTP;
headers
– definește corpul cererii HTTP; poate primi valori de tipuri diferite în funcție de formatul
body
datelor: String, Object, Blob, BufferSource, FormData, URLSearchParams etc.
Spre deosebire de cererile GET, unde parametrii se află adesea în URL (query string), în cazul cererilor POST
datele sunt de regulă trimise în corpul cererii (body).
Cererea POST trimite date către server. Asta înseamnă că în apelul Fetch API trebuie să specificăm:
că metoda este POST;
ce date trimitem (body);
în ce format trimitem datele (cel mai des JSON, prin headers).
Exemplu
Să analizăm un exemplu de pagină de login. Când utilizatorul completează formularul de login (email și
password) și apasă Login, front-end-ul trebuie să trimită aceste date către server. Una dintre modalitățile de
a face acest lucru este să folosim obiectul , care se comportă ca un „formular virtual” în JavaScript.
FormData
Codul este următorul:
1 const formData = new FormData();
2 formData.append("email", "alex@gmail.com");
3 formData.append("password", "secret123");
4
5 fetch("https://example.com/api/login", {
6 method: "POST",
7 body: formData
8 })
9 .then(r => r.json())
10 .then(data => console.log(data));
Ce am făcut în acest exemplu?
1. Am creat un obiect FormData
1 const formData = new FormData();
este folosit pentru a trimite date într-un format similar cu un formular HTML. Acest lucru este util
FormData
atunci când back-end-ul așteaptă date ca și cum ar proveni dintr-un formular.
2. Am adăugat câmpuri în formular folosind
append()
1 formData.append("email", "alex@gmail.com");
2 formData.append("password", "secret123");
Metoda adaugă o pereche cheie-valoare în corpul cererii.
append(key, value)
" " este numele câmpului (key)
email
" " este valoarea (value)
alex@gmail.com
3. Am trimis cererea POST folosind
fetch()
1 fetch("https://example.com/api/login", {
2 method: "POST",
3 body: formData
4 })
Aici se întâmplă două lucruri importante:
→ indicăm că dorim să trimitem date către server
method: "POST"
→ trimitem datele în corpul cererii
body: formData
4. Citim răspunsul serverului ca JSON
1 .then(r => r.json())
returnează un răspuns (obiect Response). Dacă serverul returnează JSON (ceea ce este cel mai
fetch()
frecvent), folosim r.json() pentru a transforma răspunsul într-un obiect JavaScript.
5. Folosim datele primite
1 .then(data => console.log(data));
În primim ceea ce serverul returnează după login, de exemplu: .

Notă pentru învățare ulterioară: Long Polling
Să presupunem că doriți ca aplicația client să primească automat notificări atunci când starea de pe
server se schimbă, de exemplu ca utilizatorul să vadă numărul actualizat de produse în stoc. În acest
caz, Fetch API clasic nu oferă o soluție optimă, deoarece fiecare cerere returnează imediat un răspuns
și nu permite așteptarea schimbărilor.
Pentru astfel de situații se utilizează long polling, care permite clientului să „asculte” serverul și să
primească actualizări imediat ce apar modificări.
Mai multe informații despre long polling puteți găsi în materialele suplimentare sub denumirea „Long
Polling”.
Notă pentru învățare ulterioară: WebSocket
Dacă doriți să explorați o metodă mai modernă de comunicare cu serverul în timp real, puteți consulta
lecția „WebSocket” din materialele suplimentare.
WebSocket permite o conexiune bidirecțională permanentă între client și server, ceea ce este
deosebit de util pentru aplicații de chat, jocuri online sau monitorizarea schimbărilor în timp real.
Când alegem FormData și când JSON?

back-end-ul așteaptă un formular (multipart/form-data);

Exemplu – trimiterea unei imagini de profil (FormData)
Dacă utilizatorul încarcă o imagine de profil, se folosește FormData deoarece permite trimiterea fișierelor.
1 const formData = new FormData();
2 formData.append("username", "ana");
3 formData.append("avatar", fileInput.files[0]);
4
5 fetch("/api/profile", {
6 method: "POST",
7 body: formData
8 });
Browserul setează automat headerul:
1 Content-Type: multipart/form-data
Exemplu – înregistrarea utilizatorului (JSON)
În cazul API-urilor REST, cel mai des se folosește JSON deoarece back-end-ul așteaptă date structurate.
1 const user = {
2 username: "ana",
3 email: "ana@gmail.com",
4 password: "ana123"
5 };
6
7 fetch("/api/users", {
8 method: "POST",
9 headers: {
10 "Content-Type": "application/json"
11 },
12 body: JSON.stringify(user)
13 });
Regulă pe care programatorii o folosesc frecvent
Dacă trimiteți fișiere → folosiți FormData
Dacă comunicați cu un REST API → folosiți JSON
În aplicațiile web moderne, JSON este cel mai frecvent format, în timp ce FormData este utilizat atunci
când este vorba despre formulare HTML sau încărcarea de fișiere.
