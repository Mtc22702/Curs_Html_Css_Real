În lecția anterioară ați învățat cum se pot trimite date prin URL folosind query string. Acum
veți vedea o altă metodă, mai practică – formularele HTML.
Când utilizatorul completează un formular și apasă butonul de trimitere, browserul trimite
datele serverului la adresa specificată în atributul action al formularului. Ceea ce este
important este că action îi spune browserului la ce adresă URL trebuie trimise datele din
formular.
Codul este următorul:
1 <form id="login-form" action="https://www.mydomain.rs/login">
2 <label class="form-label fw-semibold">Email</label>
3 <input type="email" id="email" name="email" class="form-
4 control" placeholder="">
5 <label class="form-label fw-semibold">Password</label>
6 <input type="password" id="password"
7 name="password" class="form-control" placeholder="">
<button type="submit" class="btn">LOGIN</button>
</form>
Acesta este un formular HTML simplu. Când utilizatorul apasă pe submit, datele din formular
sunt trimise la adresa care este menționată în atributul action:
https://www.mydomain.com/login. Puteți ghici dacă această adresă este relativă sau
absolută?
Dacă cineva a ales că este relativă, ar trebui să se întoarcă puțin la al doilea curs.
Adresa menționată este absolută. Dacă am fi vrut o adresă relativă, am fi scris:
action="login.php"
Acest lucru ar însemna că scriptul login.php se află în aceeași locație pe server ca și pagina cu
formularul.
De exemplu, dacă formularul se află la adresa:http://www.mysite.com, atunci datele vor fi
trimise la:http://www.mysite.com/contact.php.
Când completați formularul și apăsați LOGIN, veți observa o schimbare în bara de adrese a
browserului – acesta este efectul pe care îl vom explica în continuare.
Datele formularului sunt transmise implicit prin URL
Imaginea arată ce se întâmplă atunci când este trimis formularul de login cu date introduse.
Datele din formular sunt, în mod implicit, trimise serverului și apar în URL ca perechi
cheie=valoare. Numele cheilor sunt preluate din atributul name al câmpurilor input, de
exemplu devine în URL.
name="email" email=test@gmail.com
Modul în care vor fi trimise datele (în URL sau în corpul cererii) este determinat de atributul
method din formular, care poate fi bine-cunoscutul get sau post.

HTTP GET

adăugarea lor în URL sub forma unui query string. Asta înseamnă că numele câmpului
(atributul ) și valoarea sa apar în URL, de exemplu
name

Când nu este GET o alegere bună?
Metoda GET nu este potrivită pentru trimiterea datelor sensibile, cum ar fi parolele,
deoarece acestea apar în URL, pot rămâne în istoricul browserului sau în log-urile serverului.
De exemplu, în cazul unui formular de autentificare (login), nu este sigur ca parola introdusă
de utilizator să fie vizibilă în bara de adrese a browserului. URL-ul poate rămâne salvat în
istoricul browserului, în log-urile serverului sau chiar poate fi transmis mai departe. Asta
înseamnă că datele sensibile, precum parola, pot deveni accesibile persoanelor
neautorizate.
Pentru informații confidențiale este mai bine să se folosească metoda POST, care trimite
datele în corpul cererii HTTP.
Transmiterea datelor formularului prin metoda
HTTP POST
Când se setează post (sau POST) pentru valoarea atributului method, trimiterea formularului
generează o cerere HTTP POST, iar datele sunt stocate în corpul acestei cereri:
1 <form id="login-form" action="https://www.mydomain.rs/login"
2 method="POST" >
3 <label class="form-label fw-semibold">Email</label>
4 <input type="email" id="email" name="email" class="form-
5 control" placeholder="">
6 <label class="form-label fw-semibold">Password</label>
7 <input type="password" id="password"
name="password" class="form-control" placeholder="">
<button type="submit" class="btn">LOGIN</button>
</form>
Acum, pe elementul este setat atributul method cu valoarea . Din acest motiv,
form POST
trimiterea acestui formular va rezulta într-o cerere HTTP POST, iar datele vor fi transmise în
corpul acesteia.

Trimiterea datelor formularului prin metoda POST
Când datele formularului sunt transmise folosind metoda HTTP POST, forma în care acestea
se regăsesc în interiorul corpului cererii HTTP este definită de valoarea atributului ,
enctype
care poate fi setat pe elementul form:
– valoare implicită; datele sunt trimise ca
application/x-www-form-urlencoded
perechi cheie=valoare, similar metodei GET, cu aplicarea URL encoding-ului.
– este folosit atunci când formularul trimite fișiere.
multipart/form-data
– datele sunt trimise în text simplu; este utilizat în general doar pentru
text/plain
testare sau depanare.
Metoda POST este mai sigură pentru date sensibile (de exemplu, parole), deoarece acestea
nu sunt vizibile în URL și nu rămân în istoricul browserului.
Notă
Un formular HTML nu poate seta headere HTTP personalizate (cum ar fi X-API-Key).
Browserul nu permite acest lucru din elementul <form>.
Un formular HTML poate trimite doar:
URL-ul (action);
metoda (GET sau POST);
datele din câmpurile de input (în body sau query string);
cookie-urile pe care browser-ul le adaugă automat.
Dar headerele personalizate nu sunt posibile. Soluția folosită în practică, în cazul în care
lucrați cu servicii API care necesită API Key, este ca formularul să declanșeze JavaScript, iar
JavaScript să trimită un request fetch cu headerul, iar acest lucru îl vom aborda în lecțiile
următoare ale acestui modul.
