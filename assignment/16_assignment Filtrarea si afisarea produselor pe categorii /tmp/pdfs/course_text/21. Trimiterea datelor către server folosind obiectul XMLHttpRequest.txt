Trimiterea datelor către server
folosind obiectul XMLHttpRequest
Descarcă lecția
Până acum ați învățat cum se trimit cereri folosind obiectul XMLHttpRequest. În exemplele din lecțiile
anterioare am folosit cereri HTTP GET atunci când am solicitat anumite date de la server.
Pe lângă solicitarea datelor de la server, este la fel de importantă și trimiterea datelor către server. Procedura
de trimitere este similară exemplelor prezentate, cu diferența că în loc de cereri HTTP GET se creează o
cerere HTTP POST.
Să analizăm un exemplu de înregistrare a unor utilizatori noi.
Când utilizatorul apasă pe butonul CREATE AN ACCOUNT, trebuie să se trimită o cerere POST prin care se
înregistrează pe server un nou cont de utilizator.
Un exemplu de creare a unei cereri HTTP POST și trimitere a datelor JSON textuale către server poate arăta
astfel:

5 receivePersonalizedPromotions: true,

Explicația pașilor:
1. Creăm obiectul JavaScript care reprezintă datele utilizatorului.
user
2. Serializăm obiectul în JSON folosind – astfel serverul poate citi ușor datele.
JSON.stringify()
3. Creăm obiectul XHR și inițializăm o cerere POST către adresa

4. Setăm antetul Content-Type: application/json folosind metoda

Acest lucru spune serverului că în corpul cererii trimitem JSON.
Nu este obligatoriu, dar ajută serverul să parseze automat datele.

Notă
Pentru cererile POST, datele se trimit întotdeauna în corpul cererii, spre deosebire de cererile GET
care, în general, trimit datele prin URL.
Setarea antetelor cererii HTTP
Atunci când trimitem date către server, uneori este necesar să definim antetele cererii. Antetele cererii HTTP
(HTTP headers) sunt partea mesajului HTTP care conține informații suplimentare despre cererea în sine sau
despre clientul care trimite cererea.
Acest lucru se face folosind metoda:
1 xhr.setRequestHeader(name, value);
În acest cod:
– numele antetului (de exemplu, )
name "Content-Type"
– valoarea antetului (de exemplu, )
value "application/json; charset=utf-8"
De ce să folosim Content-Type?
În exemplul cererii POST pentru înregistrarea utilizatorului, am setat antetul:
1 xhr.setRequestHeader("Content-Type", "application/json; charset=utf-
8");
Acest lucru spune serverului că se așteaptă date JSON în corpul cererii.
Nu este obligatoriu, dar este recomandat deoarece serverul poate parsa automat datele și le poate procesa
corect.
Notă
Fără un antet corespunzător, serverul poate trata datele ca text simplu, ceea ce poate duce la erori la
procesarea JSON-ului sau a altor formate.

CORS
Până acum am ilustrat trimiterea mai multor cereri HTTP GET și POST. Unele dintre ele au fost folosite pentru
citirea conținutului fișierelor de pe serverul local, în timp ce altele au fost destinate trimiterii de date către
servere la distanță. În timpul comunicării cu serverul folosind limbajul de programare JavaScript, este
important să cunoașteți încă un concept foarte important, care are un rol decisiv în rezultatul comunicării
dintre clienți și servere pe web. Este vorba despre noțiunea CORS.
CORS (Cross-Origin Resource Sharing) înseamnă partajarea resurselor între origini diferite.
Origin (originea) este de fapt o combinație a trei informații diferite: protocolul, domeniul și portul. De
exemplu, logica JavaScript pentru trimiterea cererilor către server, care în exemplele anterioare se afla pe un
server HTTP local, avea următoarea origine:
1 http://localhost
Logica JavaScript care se află pe un server de producție poate avea următoarea origine:
1 https://www.mysite.com
Din exemplu este clar că originea reprezintă o parte a adresei URL, fără calea concretă, ceea ce permite
definirea originii clare a codului JavaScript (adică legarea acestuia de protocol, domeniu și port).
O cerere HTTP cross-origin apare atunci când JavaScript încearcă să contacteze un server care are un
origin diferit. De exemplu, o cerere HTTP cross-origin poate apărea dacă logica noastră client JavaScript care
se află la adresa http://localhost încearcă să trimită o cerere către serverul de la adresa
https://www.mysite.com.
Cereri same-origin și cross-origin
Imaginea ilustrează diferența dintre cererile same-origin și cross-origin (cu verde sunt prezentate cererile
same-origin, iar cu roșu, cererile cross-origin).
Browserele web moderne, în mod implicit, blochează cererile HTTP cross-origin din motive de securitate.
Totuși, serverele pot decide singure dacă doresc să accepte o anumită cerere cross-origin.
Din acest motiv, browserul înainte de a trimite cererea reală trimite o cerere specială preflight.
Scopul cererii preflight este acela de a permite serverului să specifice ce origini sunt permise pentru
acceptarea cererilor. Dacă serverul răspunde că origin este permis, browserul trimite abia atunci cererea
reală.
Acest mecanism permite ca cererile cross-origin să fie sigure și controlate, în loc să fie toate permise
automat.
Mod simplificat de funcționare al CORS
În imagine se pot observa câteva aspecte foarte importante ale mecanismului CORS:
1. Cererea preflight
Browserul verifică mai întâi dacă serverul permite cererea cross-origin.
Trimite o cerere HTTP cu metoda OPTIONS.
Include întotdeauna antetul Origin cu originea sa.
2. Răspunsul serverului
Serverul returnează antetul Access-Control-Allow-Origin.
Poate specifica exact ce origini sunt permise sau * dacă le acceptă pe toate.
3. Trimiterea cererii reale
Dacă serverul permite originea, browserul trimite cererea concretă (GET, POST etc.).
4. Procesarea răspunsului
Serverul răspunde la cererea reală.
Browserul transmite datele către JavaScript (de exemplu, atunci când se folosește
xhr.onload
).
