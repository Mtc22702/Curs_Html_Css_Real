Descarcă lecția
În lecția anterioară ați învățat modul de bază de comunicare cu serverul – obiectele . Totuși,
XMLHttpRequest
utilizarea obiectului are și o alternativă modernă, iar aceasta este Fetch API.
XMLHttpRequest
Folosind Fetch API, este posibil să realizați tot ceea ce a fost prezentat în lecția anterioară, dar într-un mod
ușor diferit, mai simplu și mai modern. De aceea, în această lecție vom prezenta scenarii de citire și trimitere a
datelor folosind Fetch API.
Ce este Fetch API?
Fetch API este o modalitate modernă de comunicare cu serverul în JavaScript. Reprezintă o alternativă mai
simplă și mai flexibilă față de abordarea pe care am folosit-o în lecția anterioară cu obiectul
. Astăzi, Fetch API este standardul pentru trimiterea cererilor HTTP în aplicațiile web
XMLHttpRequest
moderne.
Baza sa este metoda .
fetch()
Metoda
fetch()
Sintaxa de bază arată astfel:
let promise = fetch(url, [options]);
Metoda primește doi parametri:
fetch()
url (obligatoriu) – adresa resursei (de exemplu, fișier sau rută API).
options (opțional) – obiect prin care configurăm detaliile cererii (metoda, antetele, corpul cererii etc.).
Dacă omitem al doilea parametru, trimite automat o cerere GET:
fetch()
fetch("users.json");
Dacă dorim să trimitem POST, PUT, DELETE sau alt tip de cerere, trebuie să transmitem obiectul options și în
el să definim cel puțin metoda HTTP.
Valoarea returnată – Promise
Metoda returnează un obiect . Asta înseamnă că rezultatul nu este disponibil imediat, ci
fetch() Promise
atunci când cererea este finalizată.
De aceea folosim:
then()
catch()
finally()
sau sintaxa mai modernă:
async/await
Să recapitulăm
trimite o cerere HTTP
fetch()
returnează un Promise
răspunsul este procesat abia după ce Promise-ul este rezolvat
În această lecție vom ilustra trimiterea unei cereri HTTP prin care solicităm anumite date de la server, iar în
lecția următoare și trimiterea datelor către server.
Trimiterea unei cereri GET folosind Fetch API
O cerere HTTP GET poate fi trimisă folosind Fetch API în felul următor:
1 fetch('products.json')
2 .then((response) => {
3 return response.json();
4 });
Deoarece metoda returnează un , rezultatul cererii îl obținem definind o funcție care va fi
fetch() Promise
executată atunci când -ul este rezolvat. Această funcție este transmisă metodei .
Promise then()
Este important să înțelegem un aspect tehnic esențial: -ul returnat de nu se rezolvă abia
Promise fetch()
după ce este descărcat întregul conținut al răspunsului, ci în momentul în care serverul trimite antetele
răspunsului HTTP.
Cu alte cuvinte, confirmă că serverul a răspuns, dar corpul răspunsului nu a fost încă procesat.
fetch()
Când -ul este rezolvat, ca rezultat obținem un obiect special al Fetch API – obiectul .
Promise Response
Obiectul Response
Response este un obiect al clasei încorporate cu același nume din cadrul Fetch API. Reprezintă răspunsul
HTTP pe care îl returnează serverul și conține informații de bază din linia de stare, antete și corpul
răspunsului.
Cele mai importante proprietăți:
– codul de stare HTTP (de exemplu, 200, 404, 500);
status
– valoare boolean care indică dacă cererea a avut succes;
ok
Această proprietate are valoarea pentru toate codurile de stare din intervalul 200-299;
true
– obiect care conține colecția de antete ale răspunsului;
headers
Un antet individual se obține folosind metoda :
get()
response.headers.get('Content-Type');
Pe lângă informațiile din antete și stare, obiectul Response permite și accesul la corpul răspunsului HTTP.
Pentru aceasta sunt folosite următoarele metode:
– citește corpul răspunsului ca text simplu;
response.text()
– parsează conținutul JSON și returnează un obiect sau un șir JavaScript;
response.json()
– parsează datele și returnează un obiect FormData;
response.formData()
– parsează datele din corpul răspunsului și returnează un obiect Blob (reprezentare
response.blob()
binară a datelor, de exemplu imagini, fișiere PDF sau alte fișiere binare);
– parsează datele din corpul răspunsului și returnează un obiect
response.arrayBuffer()
.
ArrayBuffer
Toate metodele pentru citirea datelor din corpul răspunsului returnează la rândul lor obiecte .
Promise
Exemplu complet de cerere GET cu tratarea erorilor
După ce am făcut cunoștință cu proprietățile obiectului Response, putem completa exemplul:
1 fetch('products.json')
2 .then((response) => {
3 if (!response.ok) throw new Error(`HTTP ${response.status}`);
4 return response.json();
5 })
6 .then((data) => {
7 console.log("Loaded products:", data);
8 });
Prin apelarea metodei se inițiază citirea și parsarea datelor JSON din corpul răspunsului.
response.json()
Deoarece metoda returnează un Promise, este necesar să adăugăm încă un apel . Funcția sa
json() then()
callback va fi executată abia după ce datele din corpul răspunsului sunt complet preluate și parsate. Datele
parsate sunt transmise automat ca argument al funcției.
Tratarea erorilor de rețea – catch()
Pentru ca exemplul de trimitere a unei cereri GET și citire a datelor furnizate de server să fie complet, este
necesar să adăugăm și logica pentru tratarea eventualelor erori.
Este important de știut că Promise-ul returnat de este respins doar în cazul unei erori de rețea (de
fetch()
exemplu, pierderea conexiunii, imposibilitatea de a stabili legătura cu serverul și altele similare). În astfel de
situații, este activat automat.
catch()
1 fetch('products.json')
2 .then((response) => {
3 if (!response.ok) throw new Error(`HTTP ${response.status}`);
4 return response.json();
5 })
6 .then((data) => {
7 console.log("Loaded products:", data);
8 })
9 .catch((err) => {
10 console.error("Fetch failed:", err);
11 });
Tratarea erorilor HTTP (404, 500 etc.)
Spre deosebire de erorile de rețea, erorile HTTP precum:
404 (Not Found)
500 (Internal Server Error)
nu resping automat -ul.
Promise
De aceea este necesar să verificăm manual dacă cererea a avut succes:
if (!response.ok) throw new Error(`HTTP ${response.status}`);
În interiorul funcției callback care procesează rezolvarea -ului metodei se află un bloc
Promise fetch()
condițional care verifică dacă cererea a fost procesată cu succes, folosind proprietatea ok a obiectului
.
Response
Proprietatea are valoarea doar pentru codurile de stare din intervalul 200-299. Astfel
response.ok true
putem determina eficient dacă serverul a procesat cererea cu succes.
Dacă cererea nu are succes, în cod se aruncă o excepție ( ).
throw new Error(...)
O astfel de excepție este tratată ulterior la fel ca un respins, adică este activată funcția callback
Promise
transmisă metodei .
catch()
În acest mod acoperim:
erorile de rețea;
erorile HTTP;
erorile în timpul parsării răspunsului.
Exemplu
În lecțiile anterioare ne-am familiarizat cu modul în care funcționează comunicarea dintre client și server,
precum și cu trimiterea cererilor HTTP folosind JavaScript. De asemenea, ne-am înregistrat pe un serviciu
API și am obținut propriul API key, care reprezintă un identificator unic al contului nostru și ne permite să
accesăm endpoint-uri API protejate.
În acest exemplu vom folosi cheia (key) noastră API pentru a trimite serverului o cerere GET pentru preluarea
listei tuturor produselor. Cererea va fi trimisă folosind funcția , iar cheia API va fi transmisă în cadrul
fetch()
headerului HTTP X-API-Key, pentru ca serverul să poată confirma că avem permisiunea de a utiliza acest API.
După un răspuns reușit, serverul va returna datele în format JSON, pe care le vom afișa apoi în consolă și le
vom folosi în continuare în aplicație.
1 fetch('https://api.advanziaeducation.com/api/products', {
2 method: "GET",
3 headers: {
4 "X-API-Key": "d7534cbd9ee8a1d277508f05318830010270e1c3699cacf82f8ec5
5 }
6 })
7 .then(response => response.json())
8 .then(data => console.log(data));

Micro-exercițiu
În exemplul anterior am văzut cum putem trimite o cerere GET către serverul API și obține lista tuturor
produselor. Acum sarcina voastră este să aplicați același principiu și să solicitați de la server lista tuturor
categoriilor de produse.
Serverul API conține un endpoint special care returnează toate categoriile disponibile. Pentru a accesa acest
endpoint, trebuie să trimiteți o cerere HTTP GET și, în cadrul cererii, să transmiteți cheia voastră API prin
headerul HTTP X-API-Key.
Sarcina voastră este să scrieți cod JavaScript care:
trimite o cerere GET către următorul endpoint https://api.advanziaeducation.com/api/categories;
în cadrul cererii adaugă headerul X-API-Key cu cheia voastră API;
primește răspunsul serverului în format JSON;
afișează datele primite în .
console.log()
După ce scrieți codul JavaScript:
rulați proiectul folosind Live Server;
deschideți Developer Tools → Console;
verificați dacă în consolă este afișată lista categoriilor returnată de server.
Dacă totul este realizat corect, în consolă veți vedea un șir de categorii existente în sistem.
La final, iată câteva sfaturi:
Folosiți funcția pentru trimiterea cererilor HTTP.
fetch()
Nu uitați să adăugați obiectul headers în care se va afla X-API-Key.
După ce primiți răspunsul de la server, este necesar să îl convertiți în format JSON folosind
response.json().
Următorul pas
În lecția următoare veți învăța cum să trimiteți date către server folosind Fetch API, care reprezintă o
modalitate mai modernă și mai simplă de trimitere a cererilor HTTP din JavaScript.
